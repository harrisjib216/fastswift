## Verdict

The README calls it a fast replacement for SwiftData, but its only numbers compare it with other SQLite wrappers, not with SwiftData or Core Data. Against those it is 2.2x faster than GRDB with manual decoding and 6.3x faster than GRDB with Codable, and about 6% slower than Lighter.

**Why tier C:** First-party numbers from a public suite with library versions, but no hardware, OS or build configuration stated.

## Use it when

- You want SwiftData-like @FetchAll and @FetchOne observation in SwiftUI with SQL control and value types
- You already use GRDB and decode rows through Codable
- You need CloudKit sync without adopting SwiftData

## Skip it when

- You need a measured win over SwiftData or Core Data before switching: none is published
- Deployment targets below iOS 16

## How it is fast

Tables are declared with the StructuredQueries @Table macro, which generates a decoder that reads columns in order from the SQLite statement instead of going through Codable's keyed containers. GRDB underneath provides connections, transactions and change observation. Per-row cost ends up close to Lighter's generated bindings.

## What it costs

- Brings in GRDB plus several Point-Free packages (StructuredQueries, Sharing, Dependencies)
- You write SQL schemas and migrations; no model inference as in SwiftData
- Macro-based models add macro expansion to build time

## Problems with the evidence

- No SwiftData or Core Data measurements despite the replacement claim
- Hardware, OS and build configuration are not stated
- A single query shape (full scan of one table) taken from Lighter's suite
- Benchmark date inferred from the release of the measured version (1.0.0, September 2025)
